# Security closure and provider keys Implementation Plan

> Historical maintainer implementation record. Standalone contributor setup and test commands are in the repository README.

**Goal:** Finish the bounded security/release batch, then allow one Gemini, OpenAI or Anthropic key to run Misura without Google Cloud, preserving existing Vertex users.

**Architecture:** Native HTTP adapters implement existing `Brain`; persisted canonical turns remain backward compatible. A coroutine-context snapshot fixes model routing and optional-service capabilities for each agent turn, including memory checks and nested app control. Direct Google services are optional; installed apps provide fallback.

**Tech Stack:** Existing Kotlin, kotlinx.coroutines/serialization, Android SharedPreferences/Keystore, Compose and existing HTTP helpers; no new SDK, dependency, backend or gateway.

**Spec:** `docs/superpowers/specs/2026-11-20-provider-keys-design.md`

**Status:** Tasks 1–5 are committed and independently reviewed. Task 6 source verification and whole-branch review are complete; clean export and standalone checks follow the final documentation commit. Live provider access, physical-device validation and publication remain outside this batch.

**Execution order:** 1 → 2 → 4 → 3 → 5 → 6. Native adapters (Task 4) must exist before ConfiguredBrain integration (Task 3); Task 4 uses immutable credential values from Task 2 and synthetic switchable brains for interruption tests. This avoids temporary provider stubs.

## Global Constraints

- Historical maintainer work used a private worktree and local instructions. Contributors can build from the standalone README and SYSTEM §5; no private files or agent skills are required.
- No push/publication, paid provider requests, real sends/calendar writes, destructive hardware tests, phone install or OS update. Emulator fixture actions only; always `ANDROID_SERIAL=emulator-5554`.
- Existing configured phone defaults to Vertex. Never silently downgrade models/thinking or fail over to another saved account/provider.
- Google Cloud optional, as owner explicitly confirmed. Use installed Maps/browser/apps when direct services unavailable; recommend direct integration for faster turnaround without claiming measured improvement.
- No extra search key required. New installs default to selected model provider's native web search; optional Exa/Tavily/Context.dev override. Existing saved Exa stays selected. No silent model/account switch or probing all saved search keys.
- Secret fields never prefill, use saved instance state, enter prompts/logs or appear in screenshots. Existing unavailable-Keystore plaintext fallback remains a disclosed limit until separately changed; do not call storage unconditionally encrypted.
- No arbitrary custom endpoint UI initially. Native adapters are extension boundary; no speculative plugin/provider framework.
- One Gradle run at a time. Every non-trivial patch gets meaningful failing regression, relevant checks and independent read-only review before commit.
- SYSTEM remains shared backlog; doc changes accompany behavior. Landing/visual work stays separate. Completion alerts, generated apps and other roadmap work are not prerequisites for BYO keys.

## Review Focus

1. Settings change while a job is between main/memory/app-control calls: whole active turn retains same provider, model, key and capability route; next turn uses new configuration (Tasks 3/6).
2. Old/canceled/multi-call Gemini history switched to another provider: correct call/result pairing, no orphan results or foreign reasoning metadata, preserve completed outcomes without inviting replay (Tasks 4/6).
3. OpenAI-only fresh install with no Google token/project/Exa: startup and Save never contact Vertex; app/Maps/browser fallback remains offered, native Places cards do not (Tasks 2/5/6).
4. Saved secret unreadable or persistence fails while switching providers: preserve old bytes/settings and report failure, never silently replace with empty value (Task 2).
5. Malformed/refused/truncated provider reply or redirect: no partial tool execution, no credential redirect, bounded errors and cancellation (Tasks 4/6).

## Acceptance and explicit remaining limits

- One plain key from each requested provider can configure Misura and drive main/app/memory model paths without Vertex setup.
- Existing Vertex user needs no migration/re-entry. Optional Google/Exa capabilities do not silently route model requests to another provider.

Native search charges, quotas/account restrictions, attribution obligations and browser fallback limitations are disclosed and tested without paid calls.
- Live provider billing/access, own-device Keystore interruption, secure lock/OEM sleep, private-report activation and broad O1 limits require their own evidence/authorization. Keep them visible; do not relabel unknowns as done.
- This plan does not close unrelated roadmap items, landing/visual thread, completion alerts or generated apps. Owner may prioritize those after this batch.
